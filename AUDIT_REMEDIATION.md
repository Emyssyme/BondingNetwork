# MySpeedify — Urmărirea auditului și a remedierilor

Acest document urmărește constatările din „Audit Production-Ready: MySpeedify (re-audit după patch v2)”, primit la 12 noiembrie 2026. Este un registru de lucru: o constatare se consideră remediată numai după modificarea codului și verificarea criteriilor de acceptare.

## Stare la pornire

- **Audit:** constatări H1–H9, M1–M16 și L1–L6 urmărite în tabel; criteriile care depind de hosturi reale sau deployment sunt marcate separat.
- **Remediate:** H1–H2, H5–H7; M1–M3, M5–M14, M16; L1, L3, L5.
- **Parțiale / externe:** H3–H4, H8–H9, M4, M15, L2, L4, L6; validările pe hosturi Windows/Linux, migrarea/rotația credențialelor live, profilarea reprezentativă, benchmark-ul de deployment și rularea GitHub Actions rămân necesare.

## Cum se folosește

1. La începerea unei remedieri, schimbă starea în **În curs** și completează responsabilul, branch-ul/PR-ul și data.
2. Înregistrează legături către modificări și teste în coloana „Dovadă / verificare”.
3. Marchează **Remediat** doar după ce criteriul de acceptare este trecut. Folosește **Neconfirmat** când constatarea auditului nu corespunde codului curent și documentează diferența.
4. Dacă o constatare nu se aplică sau este amânată, notează motivul și decizia, nu o șterge.

## Plan de execuție recomandat

1. **Validări pe hosturi reale:** H3 are trecut egress-ul UDP pe două NIC-uri Windows; mai necesită validarea Linux și traseul tunelat end-to-end. H4/M15/L6 necesită drepturi administrative/root, TUN/Wintun și testarea traficului, rollback și readiness pe Windows/Linux. H8 necesită forwarding/firewall pe Linux real. Hostul curent nu rulează elevated și nu are adaptor Wintun instalat; configurarea TUN a fost refuzată anterior cu `WinError 5`.
2. **Credențiale și deployment:** H9 necesită rotația secretului live și distribuirea sa securizată; M4 necesită migrarea clienților v1 și eliminarea PSK-ului comun.
3. **Performanță:** L4 necesită workload reprezentativ și profil CPU compatibil (Python 3.15.0b3+ pentru Tachyon); benchmark-ul local sintetic nu certifică performanța de producție. M16 este închis pentru arhitectură și documentarea măsurătorilor locale; măsurarea pe deployment rămâne recomandată înainte de promisiuni de capacitate.
4. **CI:** L2 necesită publicarea workflow-ului și confirmarea unei rulări GitHub Actions; nu există încă rulări pentru repository.
5. După aceste validări externe, actualizează dovezile și închide constatările rămase; nu sunt necesare alte modificări locale fără rezultate noi.
